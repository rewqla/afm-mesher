# Project Overview

Програма реалізує побудову та обробку 2D трикутної сітки для маски/контуру з фокусом на `LinearTriangle` і AFM-мешинг.  
Призначення: підготовка коректної трикутної геометрії, перевірка її валідності, розрахунок базисних функцій і подальше використання в обчисленнях/візуалізації.

# Implemented Features

- `LinearTriangle` з:
  - `triangle_id` / `triangle_number`;
  - `node_ids` / `node_numbers`;
  - координатами 3 вузлів;
  - площею трикутника;
  - `physical_area`.
- Обчислення площі трикутника (signed/unsigned).
- Перевірка орієнтації та авто-виправлення від’ємного обходу.
- Обробка вироджених трикутників (`\Delta = 0` -> помилка).
- Лінійні базисні функції `\varphi_i, \varphi_j, \varphi_k`.
- Глобальна наскрізна нумерація вузлів на рівні сітки.
- Окрема наскрізна перенумерація трикутників поверх уже побудованої індексованої сітки.
- Кешування списку `LinearTriangle` для стабільності повторних викликів `Mesh.linear_triangles()`.
- Валідація геометрії та вхідних даних.
- Unit tests для `LinearTriangle`, нумерації та інтеграційних сценаріїв.

# Supported Modes

- Графічний режим редагування маски (Pen/Eraser/Fill/Shape tools).
- Режими триангуляції: `Fast`, `Balanced`, `Accurate`, `Custom`.
- Режим побудови/перевірки `LinearTriangle` у доменному шарі.
- Тестовий режим (unit/integration tests).

# Input Data

- Координати вузлів: 3 точки `Point(x, y)`.
- Номери вузлів: 3 додатні цілі `node_ids`.
- Номер трикутника: додатне ціле `triangle_id`.

Формат для `LinearTriangle`:
- `triangle_number: int`
- `node_coordinates: tuple[Point, Point, Point]`
- `node_numbers: tuple[int, int, int]`
- `meters_per_pixel: float`

# Numbering

## Node Numbering

Нумерація вузлів будується в `Mesh.indexed_mesh()`.

Поточна реалізація:
- використовується глобальний словник `key_to_node_number`;
- ключ вузла = округлені координати точки з точністю `key_precision`;
- новий вузол отримує номер під час першої реєстрації точки;
- база нумерації вузлів — `1`;
- результат зберігається в `IndexedMesh(nodes, triangles, boundary_nodes, bandwidth, index_base=1)`.

Для чого це потрібно:
- перетворити геометричну сітку `Mesh(triangles=[Triangle(...)])` у індексовану таблицю вузлів і елементів;
- забезпечити єдину наскрізну нумерацію вузлів для всієї сітки;
- підготувати дані для постпроцесингу, експорту та побудови `LinearTriangle`.

## Triangle Numbering

Нумерація трикутників виконується окремо від нумерації вузлів.

Поточна реалізація:
- базовий список `LinearTriangle` спочатку будується в `Mesh.linear_triangles()` з `IndexedMesh.triangles`;
- далі викликається `renumber_triangles()` з `mesh_postprocessing.py`;
- функція повертає новий список `LinearTriangle` з `triangle_number = 1..N`;
- база нумерації трикутників — `1`;
- `LinearTriangle` є `frozen=True`, тому перенумерація не мутує існуючі об'єкти, а створює нові.

Алгоритм перенумерації трикутників:
- для кожного трикутника береться `min(node_numbers)` як первинний ключ;
- `max(node_numbers)` використовується як вторинний ключ;
- обидва значення пакуються в `uint64`;
- `numpy.argsort(..., kind="stable")` дає стабільний порядок;
- для рівних ключів зберігається відносний порядок вхідного списку.

Для чого це потрібно:
- отримати щільну наскрізну нумерацію трикутників `1..N`;
- відокремити нумерацію трикутників від порядку створення `LinearTriangle`;
- мати стабільний порядок елементів для експорту, тестів і топологічних структур поверх одного й того самого `Mesh`.

## Caching and Stability

`Mesh.linear_triangles()` кешує результат за ключем:
- `key_precision`
- `meters_per_pixel`

Це зроблено для того, щоб:
- повторний виклик на одному й тому самому `Mesh` повертав той самий порядок `LinearTriangle`;
- після `RCM`-перенумерації вузлів не виникало повторної зміни порядку трикутників при повторному виклику;
- уникнути подвійної перенумерації трикутників на вже підготовленій сітці.

## RCM Node Renumbering

Окремо від нумерації трикутників існує `renumber_nodes_rcm()`.

Призначення:
- перенумерувати вузли сітки для зменшення ширини стрічки матриці зв'язків (`bandwidth`);
- зберегти коректну трикутну топологію при зміні номерів вузлів.

Поточний порядок у пайплайні:
- `Mesh.linear_triangles()` будує список `LinearTriangle`;
- з нього беруться `node_numbers` і формується індексована таблиця трикутників;
- `renumber_nodes_rcm()` повертає новий порядок вузлів і трикутників;
- на виході створюється новий `Mesh` з `indexed_mesh_data` і `node_order`.

# Applied Algorithms

## Triangle Area

\[
\Delta =
\frac{1}{2}
\begin{vmatrix}
1 & x_i & y_i \\
1 & x_j & y_j \\
1 & x_k & y_k
\end{vmatrix}
\]

Використовується для:
- обчислення площі;
- визначення орієнтації (знак \(\Delta\));
- перевірки виродженості.

## Linear Basis Functions

\[
\varphi(x,y)=\alpha+\beta x+\gamma y
\]

Використовується для:
- локальної апроксимації всередині лінійного трикутного елемента;
- інтерполяції вузлових значень.

## AFM Meshing (Advancing Front Method)

Використовується для:
- генерації трикутної сітки з контуру/маски;
- побудови робочої геометрії для подальшого аналізу.

### Алгоритм створення нового фронту навколо внутрішніх об'єктів

Мета: якщо всередині зовнішньої області є включення (отвори) або відкриті розрізи, AFM має стартувати не тільки з зовнішньої межі, а й з додаткових внутрішніх фронтів.

Поточна реалізація (кроки):
1. Вхідні контури діляться на замкнені та відкриті:
   - замкнені -> кандидати на shell/holes;
   - відкриті -> кандидати на cuts.
2. Замкнені контури перетворюються в полігони і класифікуються:
   - найбільший валідний полігон стає зовнішньою оболонкою (`shell`);
   - внутрішні замкнені полігони стають включеннями (`holes`).
3. `holes` нормалізуються:
   - прибираються невалідні/вироджені;
   - об'єднуються перекривні включення;
   - орієнтація та топологія узгоджуються із зовнішньою межею.
4. Відкриті контури обробляються як `cuts`:
   - спрощення без примусового замикання;
   - конвертація в полілінії внутрішніх розрізів.
5. AFM запускається через `generate_with_holes_and_cuts(boundary, holes, cuts)`:
   - базовий фронт = ребра зовнішньої межі;
   - додаткові фронти = ребра кожного отвору;
   - для cuts додаються двосторонні фронтові обмеження вздовж розрізу.
6. На кожній ітерації AFM нові трикутники будуються з урахуванням активних фронтів:
   - забороняється перетинати межі shell/holes;
   - забороняється перетинати cuts;
   - фронт локально оновлюється після додавання трикутника.
7. Результат: одна узгоджена сітка для зовнішньої області з коректним обходом включень і розрізів.

Реалізація:
- `src/presentation/triangulation_adapter.py` (`_split_closed_and_open_contours`, `_extract_cuts`, `_run_with_contours`)
- `src/application/services/obstacle_processor.py` (`extract_holes`, `normalize_holes`)
- `src/application/services/advancing_front_mesher.py` (`generate_with_holes_and_cuts`)

## Laplacian Smoothing

Використовується для:
- покращення якості трикутників після первинної генерації сітки.

Поточна реалізація:
- працює на індексованих вузлах і трикутниках;
- не дозволяє інверсію трикутників;
- після згладжування знову застосовується `RCM`-перенумерація вузлів.

## Ramer-Douglas-Peucker (RDP)

Використовується для:
- спрощення контуру перед триангуляцією (`epsilon`).

## Contour Pipeline Preprocessor

Використовується для:
- уніфікованої пост-обробки сирих pen strokes;
- стабільної валідації contour-геометрії без raster fill;
- нормалізації contours, витягнутих із завантаженого зображення.

Поточний алгоритм:
- видалення послідовних дублікатів точок за `epsilon`;
- RDP-спрощення для прибирання мікро-тремтіння;
- детекція замикання по `closure_tolerance`;
- якщо contour замкнувся раніше, ніж відпущено перо, хвіст після точки замикання відрізається;
- `last` жорстко прирівнюється до `first`;
- already-closed image contours не обробляються як хвіст сирого штриха вдруге.

Реалізація:
- `src/domain/geometry/contour_pipeline.py`

## Smart Append Contour

Використовується для:
- коректного домальовування відкритого contour без розриву;
- запобігання шпорам і дегенеративним кутам в точці snap.

Поточний алгоритм:
- визначається, до якого боку відкритого contour іде приєднання: `start` або `end`;
- існуючий contour не перевертається глобально;
- обчислюється напрямок хвоста або голови contour;
- перші точки нового штриха проектуються на цей напрямок;
- новий штрих додається в початок або кінець contour;
- результат ще раз проходить через `Contour Pipeline Preprocessor`.

Реалізація:
- `src/domain/geometry/contour_pipeline.py`
- `src/presentation/canvas.py`

## Stroke Centerline Extraction

Використовується для:
- валідації та триангуляції завантажених зображень із відкритими штрихами;
- переходу від товстої raster-лінії до полілінії centerline.

Поточний алгоритм:
- бінарна маска штриха скелетизується методом Zhang-Suen thinning;
- далі виконується трасування connected component по 8-зв'язності;
- отримана polyline використовується як input для `BoundaryValidator`.

Реалізація:
- `src/infrastructure/processing/stroke_centerline_extractor.py`

## Ear Clipping Triangulation

Використовується для:
- fallback-триангуляції, коли фронт AFM не може просунутись.

## Ray Casting Point-in-Polygon Test

Використовується для:
- перевірки належності точки полігону.

## Segment Intersection Test (orientation-based)

Використовується для:
- перевірки перетинів ребер і запобігання невалідним з'єднанням.

# Validation

- Рівно 3 координати вузлів.
- Рівно 3 `node_ids`.
- `node_ids` — додатні цілі та унікальні в межах трикутника.
- `triangle_id` — додатне ціле.
- `meters_per_pixel` — додатне finite-значення.
- Координати вузлів унікальні.
- Координати є finite-значеннями.
- Трикутник не вироджений.
- Площа додатна після перевпорядкування (за потреби).
- `Mesh` не може бути порожнім.
- `IndexedMesh.index_base` може бути тільки `0` або `1`, але поточна побудова сітки використовує `1`.

Для contour-валідації в UI/triangulation path:
- `BoundaryValidator` працює поверх `preprocess_contour` + `validate_contour`;
- відкритий contour блокує триангуляцію;
- self-intersection блокує триангуляцію;
- підсвічується тільки останній знайдений open segment;
- автодомальовування контуру відключене.
